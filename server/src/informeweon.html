🔎 Cómo funciona tu sistema (fácil)

El tráfico viaja así:

[ Tu navegador ] → [ Cloudflare 🌐 ] → [ Túnel ] → [ Nginx :80 ] → [ App :5173 ]

El túnel de Cloudflare es como una "agenda" que dice a qué puerto mandar cada nombre. Esa agenda está en el panel de Cloudflare (Networks → Tunnels), NO en tu Raspberry 🍓.

Nombre (hostname)¿A dónde va?¿Funciona?
quincha.cl→ localhost:5173✅ Sí, 200
www.quincha.cl→ ⚠️ no está en la agenda❌ 404
n8n.quincha.cl→ localhost:8080✅ Sí
ssh.quincha.cl→ localhost:22✅ Sí
gonzalo.quincha.cl→ localhost:3001✅ Sí

Cuando no encuentra el nombre en la agenda, Cloudflare responde un 404 por defecto. Por eso www fallaba 😅.

🧰 Cómo se arregla (fácil, sin romper nada)

No hay que tocar la Raspberry ni la otra web. Solo hay que anotar "www" en la agenda del túnel en el panel de Cloudflare:

  1. Entra a Cloudflare Dashboard → Zero Trust (o Networks).
  2. Ve a Tunnels → tu túnel → Public Hostname.
  3. Agrega: Subdomain = www y Domain = quincha.cl.
  4. Servicio: HTTP → URL: localhost:5173.
  5. Guarda y espera ~30 segundos. ¡Listo! 🎉

¿Prefieres que www redirija a la raíz? También se puede con una Redirect Rule: www.quincha.cl/* → https://quincha.cl/$1 (301)

🧐 ¿Y por qué "no se abría" desde otra red?

  • 👉 Si escribías www.quincha.cl (con www) → por eso el 404. Usa https://quincha.cl (sin www).
  • 👉 El otro computador podía tener DNS viejo guardado de cuando el hosting estaba en otro lado. Limpia caché: ipconfig /flushdns o prueba en incógnito.
  • 👉 Para probar sin dudas: abre desde el celular con datos móviles 📱.

El sitio NO está caído 🌍✨
